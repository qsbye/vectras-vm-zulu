# 消音器标签页（端上训练周期噪音反相消除）- 产品需求文档

## Overview

- **Summary**：在 AudioSuitZulu 中新增「消音器」标签页（Android `:app` 与 macOS desktop `:desktop` 双端同步）。用户录制几秒**固定规律（周期性）噪音**，App 在设备端实时训练一个小型神经网络拟合噪音波形；随后开启消音，App 实时跟踪噪音相位、按回路时延**提前播放反向波形**，在设备麦克风位置形成相消干涉，并绘制「噪音 vs 反相波」双波形图。
- **Purpose**：以可玩、可视化的方式实现主动噪声消除（ANC），面向风扇、电机、变压器嗡鸣等稳态周期噪声场景；同时是「录制→端上训练→实时推理」完整链路的技术演示。
- **Target Users**：玩机用户、音频/DSP 算法爱好者。

## Goals

- 完整可走通的四步流程：**录制噪音 → 设备端训练网络 → 回路时延标定 → 开启消音**。
- 真正的**设备端神经网络训练**：前向 + 反向传播 + Adam 优化器全部纯 Kotlin 实现，不引入任何第三方 NN/推理框架（用户明确选择此路线）。
- 时延补偿：自动回路标定输出链路延迟，反向波形按提前量生成；支持手动微调。
- 实时安全：失锁自动淡出静音、反噪增益缓升与上限保护，避免相位失配引发啸叫。
- 双波形可视化与训练状态透明（基频、周期性得分、loss、消音能量指标）。
- Android + desktop 功能对等，复用现有大地色主题与组件风格。

## Non-Goals

- **不做宽带/非周期噪声消除**（人声、音乐、白噪、突发声）——那是 RNNoise 类方案的目标场景；本功能对非周期内容应判定「失锁」并静音输出。
- 不做端到端通用降噪网络、不追求跨场景泛化；网络只记忆/拟合本次录制的周期波形。
- 模型持久化（v1 模型仅存于内存，退出 App 需重新录制训练；权重文件存取留待后续）。
- 不做多麦克风阵列、耳机误差麦等硬件级 ANC；**物理静区仅在设备自身麦克风位置**，不承诺整耳/整房消音。
- 不做 iOS。
- 不改动「扩音器」标签页现有功能（仅新增第三个 Tab）。

## Background & Context

- 算法依据：
  - `docs/anc-algorithm-research-cnblogs.md`：第 II.A 节周期噪声**波形合成法**（存一个周期、自适应重现）、第 III 节窄带反馈系统、LMS 自适应；文档指出二次通路时延使因果自适应困难，需 FxLMS——本功能改以「相位预测 + 提前量」直接绕开时延：周期信号的未来相位已知，可提前生成。
  - `docs/rnnoise-learning-noise-suppression.md`：混合路线——确定性信号处理（基频、回声、分带）与小型网络结合；网络必须小而快、端上只承担它擅长的部分。本功能据此把**基频检测、回声剥离、时延标定交给 DSP，波形形状拟合交给端上训练的 MLP**。
- 用户决策（2026-10-03 澄清）：① 真·设备端神经网络训练；② Android + desktop 同步；③ 自动回路标定 + 手动微调。
- 现有可复用资产：44.1kHz/mono/16bit、chunk=512 的单线程音频循环；`NlmsAec`（回声剥离）、`HowlingSuppressor`（啸叫兜底）、`WaveformController`/`Waveform`（双波形绘制，灰=原始、绿=处理后）；两端各有独立的 `dsp/` 源码树（desktop 为独立 JVM 模块，采用复制纯 Kotlin 类的既有模式）。
- 物理与工程现实：Android 音频往返时延通常 40–150ms；只有稳态周期噪声允许「预测未来」；手机扬声器声压有限，消音深度受限，以**麦克风处实测能量下降**为效果度量。

## Functional Requirements

- **FR-1 标签页与导航**：顶部 TabRow 由「扩音器/关于」变为「扩音器/**消音器**/关于」；消音器页独立持有自己的音频会话，与扩音器页互斥（同一时刻只有一个页占用麦克风/扬声器）。

- **FR-2 噪音录制**：
  - 支持录制 2.0–6.0 秒环境噪音（44.1kHz/mono/16bit），显示录制时长与电平表；不足 2.0 秒不允许进入训练。
  - 录制结束可试听回放、可重录。

- **FR-3 设备端训练（神经网络）**：
  - DSP 前处理：对录音做归一化自相关，估计基频周期 P（基频范围 30–1200Hz）与周期性置信度（相关峰强度）。置信度不足时明确提示「噪音规律性不足，建议重录」，仍允许强制训练。
  - 网络结构（纯 Kotlin）：MLP；输入为相位 Fourier 特征 `[sin,cos](2πkφ), k=1..K`，K=min(10, floor(Nyquist/f0))；两层 32 单元 tanh 隐藏层；单线性输出（该相位的噪声样本）。
  - 训练：自研 Adam（含 mini-batch、学习率调度），目标 MSE；后台线程执行，UI 显示轮次进度与实时 loss（每轮回调 ≥1 次）；真机训练时长 ≤ 30s（desktop ≤ 10s），支持中途取消。
  - 训练完成展示：基频 Hz、周期性得分、最终/初始 loss、录音波形与网络拟合波形叠加预览。

- **FR-4 回路时延标定**：
  - 训练完成后可执行标定：播放一段已知短标定信号（chirp/脉冲串），同时录音，经匹配滤波（互相关峰）估计「播放→麦收到」的总时延（样本数），结合 `AudioTrack`/`AudioManager` 报告时延做合理性校验（夹在 0–500ms）。
  - UI 显示标定结果（ms），提供 ±50ms 手动微调滑条；最终提前量 = 标定值 + 微调值。

- **FR-5 实时消音（推理与控制）**：开启后音频线程逐 chunk 执行：
  1. 回声剥离：用 `NlmsAec` 从麦克风信号减去本机反噪播放的回声（参考信号=实际播放值），得到外部噪声估计；
  2. 相位跟踪（PLL）：以网络波形为参照做归一化互相关，跟踪瞬时相位与微小频偏（允许基频缓慢漂移）；输出锁定置信度；
  3. 幅度跟踪：外部噪声周期分量 RMS 慢自适应，得到反噪增益；
  4. 反波生成：在相位 `φ(n + leadSamples)` 处由网络推理，取负、乘增益；
  5. 安全整形：增益缓升（≥1s）、输出硬限幅（默认上限 0.5 归一化）；置信度持续低于阈值 0.5s 则淡出静音，重新锁定后再缓升；
  6. 送扬声器播放。`HowlingSuppressor` 作为兜底可勾选启用。

- **FR-6 可视化**：消音中绘制灰（麦克风原始）+ 湖蓝（CanadianLake，反相播放波）双波形；显示锁定状态（锁定/搜索中）、基频、反噪增益、以及「麦克风处周期带能量：开启前 vs 当前」dB 指示。

- **FR-7 状态机**：页面状态 = `Idle（未训练）→ Recorded（已录制）→ Training（训练中）→ Ready（就绪）→ Calibrating（标定中）→ Active（消音中）`；按钮按状态使能；切页/退后台自动停止音频会话并释放。

- **FR-8 Desktop 对等**：`AudioEngine`（javax.sound.sampled `TargetDataLine`/`SourceDataLine`）实现同样的录制/训练/标定/实时消音状态机与同样的 NN/DSP 类（复制到 desktop 源码树，包名 `...desktop.dsp/anc`）；桌面 UI 提供对等控件与波形。

- **FR-9 文案与可解释性**：页面含简短说明：仅对规律持续噪音有效、静区在手机麦处、建议手机麦靠近目标位置、实验性功能。

## Non-Functional Requirements

- **NFR-1 性能**：实时音频线程每 chunk（512 采样 ≈11.6ms）处理总耗时显著小于 chunk 时长（真机目标 ≤5ms），不得出现 `AudioTrack` 欠载/`AudioRecord` 溢出导致的断续。
- **NFR-2 无新增依赖**：不引入任何神经网络、音频处理第三方库；只用 Android SDK / JDK。
- **NFR-3 兼容**：minSdk 24；低延迟输出路径可用时（API 26+ `PERFORMANCE_MODE_LOW_LATENCY`）启用。
- **NFR-4 稳定**：录制/训练/标定/消音任意阶段切页、反复启停、拒绝录音权限均不崩溃；真机 logcat 无 FATAL。
- **NFR-5 风格**：全部 Compose 声明式 UI、固定大地色主题（不随系统暗色切换），中文文案。
- **NFR-6 内存**：录音与训练缓冲常驻增量 ≤ 2MB；网络参数量级 ≤ 3k 权重。

## Constraints

- **Technical**：纯 Kotlin/JVM；Android 端 AudioRecord/AudioTrack，desktop 端 javax.sound.sampled；44.1kHz/mono/16bit/chunk=512；现有单线程执行器模型。
- **Business**：实验性演示功能，消音深度受手机扬声器/麦硬件限制，需如实标注。
- **Dependencies**：仅现有依赖 + 已存在的 JUnit（`libs.junit`，供纯 Kotlin 类单测）。

## Assumptions

- 目标噪声在录制与消音期间保持稳态，基频允许缓慢漂移（如风扇转速渐变），位置/距离大致不变。
- 标定时环境噪声与训练时同源且持续（标定信号靠匹配滤波从噪声中检出）。
- 真机实测以设备麦处的周期频带能量差为验收口径；用户接受「实验性」标签。
- desktop 无对应真机声场验证条件，桌面端以算法单测 + 回路仿真 + 构建通过为准。

## Acceptance Criteria

### AC-1: 网络训练与预测正确性（合成信号）
- **Type**: `rule`
- **Given**: 采样率 44100 的合成周期信号（基频 + ≥3 个谐波、叠加少量白噪）
- **When**: 以与 App 相同的 MLP 结构与 Adam 完成训练，并对整周期逐相位推理
- **Then**: 网络输出对真实波形的归一化 NMSE ≤ -15dB；在提前 lead 个采样处的预测与真实未来样本皮尔森相关系数 ≥ 0.99
- **Pass Condition**：JUnit 单测通过（Android `:app:testDebugUnitTest`，纯 JVM）
- **Evidence**: 测试报告输出 NMSE 与相关系数数值

### AC-2: 周期检测鲁棒性
- **Type**: `rule`
- **Given**: 已知基频的含噪合成周期信号，以及白噪/啁啾两类非周期信号
- **When**: 调用基频/周期性检测
- **Then**: 周期信号基频估计误差 ≤ 1% 且置信度 ≥ 阈值；非周期信号置信度低于阈值（判定不可训练）
- **Pass Condition**：JUnit 单测通过
- **Evidence**: 测试报告

### AC-3: 回路时延标定正确性
- **Type**: `rule`
- **Given**: 标定信号经过已知样本延迟并叠加噪声的合成录音
- **When**: 执行匹配滤波时延估计
- **Then**: 估计延迟与真值误差 ≤ 2 采样；无信号时返回「标定失败」而非错误数值
- **Pass Condition**：JUnit 单测通过
- **Evidence**: 测试报告

### AC-4: Android 构建与全流程
- **Type**: `rule`
- **Given**: debug 构建安装到真机
- **When**: 走通 录制(≥2s) → 训练（进度/loss 可见、可取消）→ 时延标定（显示 ms）→ 开启/关闭消音 → 切页/后台返回
- **Then**：`:app:assembleDebug` 成功；真机无崩溃；三个 Tab 均可切换；音频会话随状态正确启停释放
- **Pass Condition**：构建成功 + 真机操作录屏/日志无 FATAL
- **Evidence**: gradle 输出、logcat、真机截图

### AC-5: Desktop 构建与对等性
- **Type**: `rule`
- **Given**: shadowJar 构建
- **When**: 执行 `:desktop:shadowJar` 并启动 jar
- **Then**: 构建成功，消音器页控件齐全（录制/训练/标定/微调/开关/波形），算法类与 Android 端除音频后端外一致
- **Pass Condition**: 构建成功 + 文件对等性核对
- **Evidence**: 构建产物、源码 diff 核对

### AC-6: 真机消音实效
- **Type**: `rubric`
- **Dimension**: 外部固定周期声源（音箱播放风扇/电机录音，距手机 0.5–1m）下，设备麦处基频及主要谐波频带能量在消音开启后的下降量
- **Scale**: 1-5
- **Anchors**: 1 = 无可测下降或明显放大/啸叫；3 = 主频带下降 3–6dB 且无啸叫；5 = 主频带下降 ≥10dB，谐波整体下降、听感可辨
- **Pass Threshold**: >= 3（达不到 3 则保留功能但标注实测数值与「实验性」并经用户确认）
- **Evidence**: logcat 周期带能量指标或频谱截图、实测 dB 记录

### AC-7: 失锁安全
- **Type**: `rule`
- **Given**: 消音运行中突然切换为白噪/静音/大幅改变声源
- **Then**: 0.5s 内锁定状态变「搜索中」且反噪输出淡出静音；不产生持续啸叫；进程无异常
- **Pass Condition**: 真机操作 + logcat 验证
- **Evidence**: 操作记录、日志

### AC-8: 交互与视觉质量
- **Type**: `rubric`
- **Dimension**: 大地色一致性、状态机清晰度、波形流畅度、中文文案与说明完备性
- **Scale**: 1-5
- **Anchors**: 1 = 风格割裂/状态不可感知；3 = 功能完整但有明显粗糙处；5 = 与扩音器页浑然一体、波形 ≥25fps 无卡顿、每步操作都有反馈
- **Pass Threshold**: >= 4
- **Evidence**: 真机截图/录屏、对照扩音器页

### AC-9: 无第三方 NN 依赖
- **Type**: `rule`
- **Given**: 两端构建脚本与新增源码
- **When**: 检查依赖声明与 import
- **Then**: 无任何 NN/ML/第三方音频库；网络前向反向/Adam 均为项目内 Kotlin
- **Pass Condition**: grep/人工核对通过
- **Evidence**: 构建脚本与源码检查记录
